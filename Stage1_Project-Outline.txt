*Quality Assessment Framework (QAF)** that converts multiple runtime metrics into a single, meaningful **Quality Index (QI)** for a microservice system.

# Proposed Research Title

**"Design and Development of a Lightweight Runtime Quality Assessment Framework for Cloud-Native Microservice Applications"**

Alternative titles:

* **Development of a Runtime Quality Index Framework for Cloud-Native Microservices**
* **A Lightweight Framework for Runtime Quality Assessment of Microservice-Based Applications**

# Background

Modern microservice applications generate a huge number of runtime metrics through monitoring tools.

Examples include:

* CPU Usage
* Memory Usage
* Response Time
* Error Rate
* Availability
* Throughput
* Network Latency
* Request Success Rate

Tools such as Prometheus and Grafana collect these metrics, but they generally display them separately. Developers and operators must interpret multiple dashboards to assess overall system health.

This research proposes a framework that integrates these metrics into a single **Quality Index**, enabling easier assessment and comparison of system quality.

---

# Research Problem

Existing monitoring platforms:

✔ collect metrics

✔ display dashboards

✔ generate alerts

But they do **not** answer questions like:

* Is the system healthy overall?
* Is service quality improving or degrading?
* Which microservice contributes most to quality degradation?
* Can two deployments be objectively compared?

Developers often rely on manual interpretation.

---

# Research Gap

Current studies focus on:

* Monitoring
* Observability
* Logging
* Distributed tracing

Few provide a **runtime quality evaluation framework** that:

* combines multiple quality attributes
* assigns weights
* produces a single quality score
* identifies low-quality services automatically

This is the proposed contribution.

# Aim

To develop a lightweight framework that evaluates the runtime quality of cloud-native microservices using multiple runtime metrics and computes a unified Quality Index.

# Quality Index Formula

One possible weighted model:

[
QI = w_1P + w_2R + w_3A + w_4E + w_5S
]

Where:

* P = Performance Score
* R = Reliability Score
* A = Availability Score
* E = Resource Efficiency Score
* S = Scalability Score

Weights:

```
Performance = 30%

Reliability = 25%

Availability = 20%

Efficiency = 15%

Scalability = 10%
```

You can also determine weights using methods such as the **Analytic Hierarchy Process (AHP)** or the **Entropy Weight Method**, which adds a stronger research component than manually assigning weights.
